# ha

Личные Home Assistant blueprints и связанные конфиги/скрипты.

## Blueprints

### `blueprints/automation/stellalupus/ac_climate_control.yaml` (v2, актуальный)

Климат-контроль кондиционера: **time-proportioning (duty-cycle)** вместо
простого bang-bang гистерезиса. Пересчитывает на каждом такте "скважность"
(duty) — долю времени в текущем окне, которую кондиционер должен провести
в `cool`, пропорционально отклонению ПРОГНОЗИРУЕМОЙ (по производной, с
горизонтом упреждения) температуры от цели. Прогноз гасит тепловую
инерцию кондиционера (после команды "хватит охлаждать" комната по инерции
ещё проседает на 0.3–0.6°C).

Отдельно, троттлящимся offset-трюком, корректирует уставку под реальную
температуру в помещении, компенсируя неточный/дрейфующий встроенный
датчик кондиционера — с защитой от применения устаревших данных, если
встроенный датчик давно не обновлялся.

Требует, помимо стандартных датчиков/helper'ов:
- derivative-helper (скорость изменения температуры) на основе внешнего
  датчика температуры комнаты;
- два служебных `input_datetime` (метка времени смены режима, метка
  времени коррекции уставки) — используются как таймер минимального
  интервала между переключениями, независимый от `last_changed`
  climate-сущности.

Смена hvac_mode дополнительно защищена от гонки/двойного переключения
тремя слоями: `mode: single`, собственный `input_datetime`-таймер,
нативный `condition: state ... for: {seconds: 3}`. На практике очень
редкие (несколько раз в сутки, 5–20мс) повторные переключения всё ещё
случаются даже при всех трёх защитах — на точность поддержания
температуры это не влияет, причина не до конца выяснена (возможно,
артефакт отчёта режима облачным API кондиционера).

Выделен как blueprint из двух дублирующихся автоматизаций
(`Кондиционер гостиная: климат-контроль` и `Кондиционер спальня: климат-контроль`)
в основном HA — логика идентична, отличались только entity_id.

**Импорт в Home Assistant:**

Settings → Automations & Scenes → Blueprints → Import Blueprint →

```
https://github.com/StellaLupus/ha/blob/main/blueprints/automation/stellalupus/ac_climate_control.yaml
```

или через MCP-инструмент `ha_import_blueprint`.

**Обновление после правок в этом репозитории:** заново открыть тот же URL
через «Re-import blueprint» — `source_url` в файле уже на него указывает.

### `blueprints/automation/stellalupus/ac_presence_power.yaml` (не используется)

Изначально включал/выключал кондиционер по присутствию (приезд/подъезд к
дому → включение, полный уход → выключение). На практике трекеры
присутствия оказались недостаточно надёжны (ложные geofence-переходы без
GPS-фикса, залипание координат на многие часы) — автоматика иногда
выключала кондиционер, пока человек был дома. Автоматическое включение
убрано в v2 (оставлено только выключение при уходе), но по факту сами
автоматизации на основе этого blueprint'а сейчас **удалены** из HA —
presence-контроль полностью отключён до появления более надёжного
источника присутствия. Файл оставлен в репозитории на будущее.
